# v0.6 私人空间、分享与在线更新

## 私人空间

上传默认只对上传者和超级管理员可见。「我的私人空间」包含自己上传的图片，公开后的图片仍留在其中，并标记公开状态。「公共空间」显示所有已公开图片；「全部资产」显示当前账号有权限访问的图片。上传者可批量公开、取消公开。

账号名 `admin` 自动升级为超级管理员。其「所有私人空间」可按上传者筛选，也可在详情或批量工具栏修改上传者。普通管理员仍保留系统管理权限，但图库访问遵守本人／公共空间权限。超级管理员账号不能停用或降级，其他管理员不能修改其密码。

已有图片在迁移 `0005` 后归属 `admin`，**保留原来的公开状态**。目录扫描发现的新图片归属 `admin`，默认私有。上传去重改为同一媒体库、同一上传者内按 SHA-256 去重，不将不同用户的私人图片合并。转移上传者遇到目标账号已有同库同哈希资产时返回冲突，不合并或丢弃整理数据。

搜索、数量、搜索建议、详情、缩略图、原图、附件、工作流、整理接口及导出均校验访问权限。普通用户看不到别人的导入任务。取消公开后，先前包含该图的导出包也不能再由无权限用户下载。

全局标签、翻译和普通集合仍为共享组织资料；将图片提示词分组设为全局组是显式共享该组词条。系统管理员依然拥有完整备份和部署权限，因此此功能不是对服务器维护人员的加密隔离。

## 分享图链

上传者或超级管理员在图片详情选择 1、7、30 天后生成图链。无需登录即可访问独立的只读页面，查看图片、生成参数、角色、提示词分组、标签、原始元数据及附件，复制内容、下载原图。分享不公开个人评分、收藏、私人备注或托管文件路径。

链接使用 256 位随机令牌，数据库仅保存令牌哈希。完整链接只在创建时返回，请及时复制；之后可创建新链接或撤销已有链接。原图、缩略图、附件的每次读取均验证有效期。过期、撤销、回收站、创建者停用、取消公开或转移上传者会令相应链接失效。私有图片也可以单独限时分享，无需先公开到公共空间。

分享地址使用当前访问的网站域名。若当前地址是 `localhost`，其他设备不能通过该地址访问；请先用接收者可连接的局域网地址或 HTTPS 域名访问本站后再生成图链。分享不会自动上传图片到第三方云盘。

## 首次从 v0.5 升级

旧版本没有在线更新入口，首次需要将 v0.6 ZIP 覆盖到**原安装目录**，保留原 `.env`、项目名和数据卷，关闭旧 EXE 后替换启动器，再启动服务。也可在 Git 检出目录更新源码后执行 `docker compose up -d --build`。建议先在设置中创建完整备份。

v0.6 的 Compose 包含 `app`、`worker`、`postgres`、`updater`。`updater` 独占 Docker socket 的挂载，并挂载项目目录；app/worker 没有 Docker socket。该更新服务具有部署权限，不应对外发布端口。应用通过专用控制卷提交固定仓库的更新请求。

## 后续在线更新

管理员进入「设置 → GitHub 在线更新 → 检查更新 → 更新到新版本」。服务器固定连接 `DuesCheese/GenMediaVault` 的最新正式 Release，校验 ZIP SHA-256、文件清单、版本和路径，不接受客户端提供任意 URL 或命令。

1. 下载并验证发布包，先构建新镜像，此时现有服务继续运行。
2. 暂停写入和 worker，停止 app/worker，保存 PostgreSQL 自定义格式快照和被替换源码。
3. 保留 `.env`、Compose 项目名、数据卷、端口和原索引目录挂载，替换代码并启动新 app/worker，执行数据库迁移及健康检查。
4. 成功后恢复写入。失败时恢复数据库、源码及旧镜像；若 Docker 自身不可用，需管理员按下文恢复。

升级控制数据和备份位于 `<项目名>_update_control` 卷的 `/control/updates/<任务 ID>/`，不会自动删除。该升级备份包含数据库和源码，不复制全部图片；升级不修改媒体文件，完整媒体备份仍使用设置中的「系统备份」。构建、备份和升级需要额外磁盘空间以及服务器访问 GitHub、镜像／依赖源的网络。

在线更新应用和 worker 后，更新器继续运行当前进程；下次使用启动器启动或执行 `docker compose up -d --build updater` 会升级更新器本身。Windows 正在运行的 EXE 不能被覆盖，新 EXE 暂存为 `GenMediaVault.update.exe`，关闭启动器后可替换原 `GenMediaVault.exe`。

## 中断恢复

状态不确定时不要重复执行迁移。首先运行 `docker compose logs --tail=100 updater app` 并确认具体升级任务目录。控制器重启发现未完成请求会报告失败，保留全部备份；不会自动重放数据库迁移。

如自动回滚失败，在维护窗口停止 app/worker，用 `docker compose cp updater:/control/updates/<任务 ID>/database.dump backups/pre-update.dump` 导出对应的升级前数据库；同样复制该任务目录的 `previous` 源码到单独目录以便检查。按 [部署恢复文档](OPERATIONS.md) 的 PostgreSQL 恢复流程恢复该快照及对应源码，再启动服务。务必选取同一次升级的源码和数据库，保留现有媒体卷和 `.env`。也可用升级前下载的完整备份恢复到新 Compose 项目。

此版本的迁移不能就地降级；退回旧版必须恢复升级前数据库。
